# Примерка причёсок на своём фото

Скрипт берёт ваш портрет, прогоняет его через Gemini с набором промптов
из `styles.json` и складывает результаты в папку вместе со страницей
для сравнения бок о бок.

## Запуск

```bash
export GEMINI_API_KEY='...'          # https://aistudio.google.com/apikey
pip install requests                  # больше ничего не нужно

python3 tools/hairstyle_preview.py photo.jpg
open previews/index.html
```

Ключ держите в переменной окружения. В репозиторий он попасть не должен —
`.gitignore` закрывает `previews/`, `.env` и картинки.

## Наборы

| Команда | Что даёт |
|---|---|
| `--set styles` *(по умолчанию)* | шесть финальных причёсок из гайда |
| `--set stages` | как это выглядит на 3-м, 6-м и 10-м месяце |
| `--set all` | всё сразу, девять картинок |
| `--only curtains,flow` | только названные варианты |

Прочие флаги: `--out <папка>`, `--model <имя>` (по умолчанию модель
подбирается запросом к API, а не захардкожена), `--styles <путь>`.

## Какое фото брать

От исходника зависит больше, чем от промпта:

- **анфас**, голова прямо, лицо целиком в кадре;
- **сухие волосы** — на мокрых модель «дорисует» плотность, которой нет;
- ровный дневной свет, без вспышки и без контрового;
- без головного убора и без очков на лбу.

## Чего ждать и чему не верить

Модели редактирования склонны **улучшать** линию роста, даже когда их прямо
просят этого не делать. В `IDENTITY_GUARD` внутри скрипта прописан запрет
трогать лицо и опускать линию роста, но гарантии он не даёт.

Поэтому правило одно: **сравнивайте с оригиналом, а не с ожиданием.**
Если на картинке виски вдруг заросли — это артефакт модели, а не прогноз.
Ценность превью в форме и посадке причёски, а не в плотности волос.

Вариант `bun` (низкий пучок) сделан намеренно невыгодным — он нужен, чтобы
увидеть, как натяжение назад открывает углы, а не чтобы вдохновиться.

## Генерация прямо в диалоге: MCP

Чтобы картинки появлялись в разговоре, а не отдельной командой, в корне
репозитория лежит `.mcp.json` с двумя серверами. Ставить ничего заранее не
нужно — `npx` подтянет пакет при первом запуске.

```bash
export GEMINI_API_KEY='...'      # https://aistudio.google.com/apikey
# и/или
export OPENAI_API_KEY='...'      # https://platform.openai.com/api-keys

cd <клон этого репозитория>
claude
```

Claude Code увидит `.mcp.json` и **спросит разрешение на каждый сервер** —
подтвердите тот, ключ от которого у вас есть. Проверить состояние: `/mcp`.

Дальше можно просто попросить в диалоге: «примерь на `photo.jpg` шторки
длиной 14 см, лицо и линию роста не трогай».

### Какой из двух брать

| | `gemini-image` | `openai-image` |
|---|---|---|
| пакет | `@houtini/gemini-mcp` | `openai-gpt-image-mcp-server` |
| модель | Nano Banana Pro | gpt-image-1.x |
| правка | описанием, без маски | **инпейнтинг по маске** |
| лицо | сохраняет хорошо | `input_fidelity` — сохранение лица явной опцией |
| плюс | правки многоходовые: «а теперь чуть короче» | вне маски пиксели не трогаются вообще |

Коротко: **Gemini** — быстрее и проще, тот же ключ, что и у скрипта выше.
**OpenAI** — если нужна гарантия, что лицо не поплывёт: маска задаёт зону
правки, и всё вне её остаётся исходным. Для «поменять только волосы» это
технически более честный инструмент.

Ничто не мешает включить оба и сравнить.

### О чём стоит знать

Оба пакета — **сторонние community-проекты**, не официальные сборки Google
или OpenAI. Запуская их, вы выполняете чужой код локально и отдаёте ему свой
API-ключ. Версии в `.mcp.json` закреплены жёстко: обновлять — осознанно,
а не автоматически. Если это смущает — скрипт выше делает ту же работу
и ходит напрямую в API Google, без посредников.
